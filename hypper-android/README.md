# hypper-android — APK (Rust-ядро + Android UI)

Приложение для телефона: создаёт комнату, строит стену мониторов и гоняет на
неё кадры. Сетевой слой — Rust (`../hypper-rust`), UI — обычный Android (Java),
связка через JNI.

## Сборка

1. Rust-библиотека под arm64:

```bash
cd C:\Work\Hypper\hypper-android
cargo build --release --target aarch64-linux-android
```

Линкер NDK прописан в `.cargo/config.toml` (NDK 26.1.10909125).

2. Положить `.so` в jniLibs (уже сделано, повторить при изменениях):

```powershell
Copy-Item target\aarch64-linux-android\release\libhypper_android.so `
  android\app\src\main\jniLibs\arm64-v8a\ -Force
```

3. APK:

```powershell
cd android
$env:JAVA_HOME="C:\Work\Hypper\tools\java\jdk-17.0.21+9"
$env:ANDROID_HOME="C:\Users\USER\AppData\Local\Android\Sdk"
C:\Work\Hypper\tools\gradle\gradle-8.7\bin\gradle.bat assembleDebug
```

Готовый файл: `android\app\build\outputs\apk\debug\app-debug.apk`.

Установка на телефон:

```powershell
adb install -r android\app\build\outputs\apk\debug\app-debug.apk
```

## Что делает приложение

Поля: комната, колонки, ряды, кадров/с, лимит игроков, пароль, режим
(0 Free / 1 Private / 2 Adventure), видео, стартовая секунда и время ожидания
загрузки игрока. По умолчанию режим Free. Кнопки **Старт** / **Стоп**, ниже — лог.

После запуска (в отдельном потоке JNI):

1. Auth на Photon, создание комнаты (MaxProps 1000 / MaxVehicles 40).
2. Подключение к игровому серверу по токену, вход в комнату.
3. Ждёт входа игрока и его Instantiate-события (до указанного таймаута), затем
   спавнит стену `cols x rows` (по умолчанию 22x12 текстовых пикселей на монитор
   при размере 42%, шаг 1.73 x 1.06 м).
4. Если указана ссылка, загрузка mp4 и декодирование кадров через `MediaCodec`
   (последовательный декодер, 1x по времени видео; при ошибке — откат на
   `MediaMetadataRetriever` с `OPTION_CLOSEST`); кадр передаётся JNI в Rust,
   который обновляет мониторы Photon. Поддерживаются прямые HTTP(S) mp4 и
   YouTube-ссылки форматов `youtu.be`, `watch?v=`, `/shorts/`, `/embed/`, `/live/`.
5. Если ссылка пустая или видео не разрешилось, работает тестовый градиент.

YouTube сейчас разрешается встроенным `youtubei` Android-клиентом и загружается
в блоках Range (на проверенном ролике — mp4 около 90 МБ). Для видео, требующих
авторизации/возрастного подтверждения, это может не сработать. Нужен интернет;
полученный файл сохраняется в app cache и переиспользуется при повторном старте
с той же ссылкой (очистка кэша приложения удалит его).

Передача каждого изменившегося состояния монитора — отдельное Photon-событие.
ACK/retransmit обслуживаются между пакетами; при входе нового игрока выполняется
полный resync стены. На слабых телефонах/больших стенах фактический FPS ниже
заданного. Сначала проверьте на 3x2 или 5x3, затем увеличивайте стену.

### Частота кадров

- `MediaMetadataRetriever` с `OPTION_CLOSEST_SYNC` отдаёт **только ключевые
  кадры** (в проверенном ролике они раз в ~2 с), поэтому картинка «менялась раз
  в 2 секунды» даже при 6 fps. Точный кадр (`OPTION_CLOSEST`) честный, но на
  телефоне декодируется ~0.5 с на кадр (≈2 fps).
- Рабочее решение — `VideoPump` на `MediaCodec`: последовательное декодирование
  с привязкой к реальному времени (1x). На проверенном видео — 5–6 кадров/с при
  стене 7x5 (22x12 на панель); дальше упирается в отправку Photon.

### Трафик и устойчивость соединения

- Цвета в тексте панели сжимаются RLE: `<color=#ABC>███</color>` вместо тега на
  каждый пиксель. Это в разы уменьшает размер события (сервер может разорвать
  соединение при слишком большом потоке).
- Серверный `Disconnect` теперь распознаётся: в лог пишется
  «соединение потеряно: … (Disconnect, код 0x..)» и стена останавливается,
  вместо бесконечных «кадр N» в пустоту.
- При старте поднимается foreground-сервис `PumpService` (уведомление
  «Hypper TV»), чтобы комната и кадры жили, когда вы переключаетесь в игру.

### Важные детали, найденные при сверке с `hypper_tv.py`

- **Зеркало и переворот.** Monitor показывает текст не только зеркально по X
  (поворот на 180° вокруг Y), но и **перевёрнутым по вертикали**. Поэтому кадр
  каждой панели пре-зеркаливается по X и пре-переворачивается по Y
  (`cell_text_from_frame`). Без Y-переворота мозаика выглядит как «неверный
  порядок картинок»: строки внутри каждой панели идут снизу вверх.
- **Ёмкость текста.** Размер текста не масштабируется линейно, поэтому сетки
  подбирал замерами по снимкам. Сейчас по умолчанию **22x12 при `size=42`**.
  Замер на одном мониторе (красный фон, зелёные пиксели): при 18x10@50 текст
  покрывал ~81% площади, красными оставались межстрочные зазоры и ~2px сверху
  и снизу. Зазоры — это line spacing шрифта (≈10-15% высоты строки), их нельзя
  убрать тегом `<size>`; при более плотной сетке (22x12@42, 29x16@31) они
  становятся субпиксельными и сливаются с пикселями.
  Для сравнения: старый `hypper_tv.py` (12x8@50) даёт ~61%x77%, его же
  `Optimized.py` (9x3@136) — ~82%x81%.
- **Фон панели чёрный.** `Monitor.Color = "#000000"` — как в старом скрипте.
  Именно это убрало ощущение «пустоты»: непокрытые края и межстрочные щели
  сливаются с чёрной рамкой, а не светятся белым. Подгонка фона под картинку
  убрана.
- **view id.** Sub-id начинается с 800 (`actor*1000 + 800 + i`): младшие id
  заняты объектами самой игры, и мониторы с ними терялись/перезаписывались.
- **Высота стены.** На склоне нижний ряд уходил под землю, если стоять чуть
  выше/дальше. По умолчанию нижний ряд ставится на 2.0 м (было 1.2); центр
  можно задать полем «Центр стены по Y» (`cy`, как `--cy` в Python).
- **Один кадр на цикл.** Перед рассылкой стены кадр фиксируется, иначе разные
  панели успевали взять разные кадры видео.
- **Калибровка.** Галочка «Калибровка» рисует цвет по колонке, яркость по ряду
  и белый маркер в верхнем-левом углу — по снимку сразу видно переворот/сдвиг.
- **Фон не подгоняем.** Цвет фона — константа `#000000` (как в старом
  скрипте); динамическая подкраска под картинку убрана.
- **Фон монитора.** Monitor принимает только короткий hex `#RGB`
  (6-значный даёт чёрный). Этот же фон виден в межстрочных щелях.
- **Проверка порядка.** Есть тестовое видео-сетка 7x5 с номерами 1..35
  (`phone/make_walltest.py`, `walltest.mp4`): на стене номера должны идти
  слева-направо и сверху-вниз. Дополнительно снимок стены сверяется с кадром
  исходника по средним цветам клеток (корреляция ~0.65; при перепутанных
  строках/колонках — около нуля).
- **Запуск из ADB.** Параметры можно передать интентом:
  `adb shell am start -n com.hypper.tv/.MainActivity --es room Test --es password 1234 --es wait 30 --es url https://youtu.be/ID --ez pattern true --ez autostart true`.

## Ограничения текущей версии

- только arm64-v8a (`aarch64-linux-android`);
- видеокодеки зависят от Android; на больших стенах частота кадров ограничена
  сериализацией/передачей событий Photon;
- повторное создание уже занятого имени возвращает Photon `32766`
  (`GameIdAlreadyExists`); используйте другое имя комнаты;
- внешний JoinGame после прежнего Android CreateGame ранее возвращал `32758`.
  Путь комнаты теперь повторяет Python-оригинал (PlayerProperties и закрытие
  Master peer перед GameServer). Повторная проверка блокируется текущим таймаутом
  Photon CONNECT (`no VERIFY`) и должна быть сделана при доступности сервера;
- сетевой wall-FPS зависит от телефона и числа мониторов; передача видео
  пропорционально замедляется с ростом стены;
- подпись debug-ключом, для маркета нужен release keystore.
